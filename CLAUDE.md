# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`bambu-hando`: a Node/TypeScript CLI + Ink TUI that reads filament profiles (from the SpoolmanDB community database, or a JSON file/URL) and pushes them to two places at once (and `bambu-hando labels` prints QR spool labels for SpoolEase spools):
1. BambuStudio custom filament preset JSON files on disk (Linux + macOS only)
2. A SpoolEase console over its encrypted LAN REST API (custom-filaments CSV + one spool record per profile)

It was ported from Python; the Python code lives only in git history (before `bfac163`).

## Commands

```bash
npm test                                   # tsc build to dist/, then vitest run (e2e needs dist/)
npx vitest run test/colors.test.ts         # single file
npx vitest run -t "masks the security key" # single test by name
npm run typecheck                          # tsc over src + test, no emit
node dist/bin.js --source test/fixtures/source.json --skip-spoolease --dry-run   # headless
node dist/bin.js tui --source test/fixtures/source.json                         # TUI (needs a real TTY)
npm run tui:snap -- "wait=Spools" snap=spools key=tab snap=add -- --source spoolmandb     # TUI screens as text (your real HOME)
```

`scripts/tui-snap.mjs` runs the built TUI in a real pty rendered by `@xterm/headless` and prints screens exactly as a terminal shows them (the in-process `ink-testing-library` renderer measures ambiguous-width characters such as `™` differently, so check layout changes with it). It only reads unless your steps apply a run.

ESM with `module: nodenext`: relative imports must use `.js` extensions even from `.ts`/`.tsx`. Dependencies are pinned exact (`--save-exact`); prefer versions at least two weeks old.

## Architecture

- **`sync.ts` is the core**, shared by both front ends: `runSync(options, onEvent)` writes all presets first (`writeMany`), then SpoolEase: `testKey` → `setCustomFilamentsCsv` → `addOrEditSpool` per profile. It emits `stage` / `preset` / `spool` / `warning` events for live progress and returns `{ presets, results }`. Key rejection or an unreachable console throws `KeyCheckError` before anything is sent. A failed CSV upload marks every profile's SpoolEase status failed and skips spool creation (spools reference CSV codes). Network errors become `failed` statuses, never crashes.
- **Linking**: `FilamentProfile.filamentId` (source `slicer_filament_code`, else `"P"` + md5(name)[0:7], BambuStudio's scheme) is the single ID in the preset's `filament_id`, the SpoolEase CSV code, and spool `slicer_filament`. Verified upstream: BambuStudio reads top-level `filament_id` from user preset JSON (`Preset.cpp`); SpoolEase stores ONE custom-filaments CSV and overwrites it on POST (`app_config.rs set_filaments`), parses it with naive `split(',')` (so names must be comma-free), and creates a new spool for every add-edit with empty `id`. Hence sync GETs and merges the CSV before writing (never writes if the read fails), and with `createSpools` GETs `/api/spools` (headerless CSV, `slicer_filament` is column 12) to skip existing ones. Spools are created by default; `--skip-spools` / the TUI's "Create spools" toggle turn them off.
- **Statuses**: each `SyncResult` has `bambuStatus` / `spooleaseStatus` of `written`, `planned` (dry-run: no disk, no writes to SpoolEase), `skipped`, or `failed`. Only `failed` → exit 1; `KeyCheckError` and usage errors → exit 2.
- **Headless CLI** (`cli.ts`, entry `bin.ts`): `util.parseArgs`, flags identical to the old Python CLI, the SpoolEase console resolved once for every command (`consoleSettings` in `spooleaseConfig.ts`, so nothing saved for one console goes to another: host = flag, `SPOOLEASE_HOST`, `tui.json` `console.host`, the SpoolEase build of BambuStudio's saved settings, and a given host equal to `tui.json`'s or BambuStudio's counts as that source; port/HTTPS = flags, else `tui.json`'s when it saves no host or the same host, else 80/off (BambuStudio's address port is never used; `--no-spoolease-https` overrides a saved HTTPS); key = flag, `SPOOLEASE_SECURITY_KEY`, else the keyring's (`SECRETS.spoolease`) when `tui.json` saves no host or the same host, else BambuStudio's for BambuStudio's host, else the keyring's, best effort (an unreachable keyring gives none); only address and key are read from BambuStudio, the key as stored, never printed; Settings saves host, port and HTTPS together whenever one of them or the key changes), prints a **snake_case** JSON report (kept for compatibility with consumers of the Python report). `bambu-hando check` (`checkCommand`) runs the TUI's sync check headless through the same `readCheck` (`syncCheck.ts`, which holds the report lines too so the headless path never loads Ink): text or `--json`, exit 1 when there are problems. Everything but `tui` and `key` writes through `printableOutput` (`terminalText.ts`), which shows control characters and bidi overrides from consoles and APIs as `\uXXXX` (so piped JSON keeps its data); the TUI's `ui/text.ts` helpers draw text through `printableLine`, which drops them. `main(argv, io)` takes injectable stdout/stderr for tests; `bin.ts` exists only so importing `cli.ts` has no side effects.
- **Empty spool weights** (`spoolWeights.ts`): before `runSync`, and only when spools are created, both front ends `checkKey` then read SpoolEase's `/spools-catalog` (plain text) and `/api/spools-config` (the user's list), dry-run included, and group profiles by brand (`brandKey`: letters and digits). Rules: one catalog row → used without asking; several → the TUI's Weights page (Add tab, `tabs/add/weights.ts` + `WeightsView.tsx`; choices remembered per brand in `tui.json`) with those rows plus the source's weight and unspecified or headless exit 2 listing ready-to-paste `--spool-weight "<brand>=<grams>"` lines; none → source's weight (default) or unspecified (0, which SpoolEase fills in on the first full weigh). Unreadable lists → warning, source weights.
- **Spool labels** (`labels.ts` content, `labelPdf.ts` drawing/printing, `bambu-hando labels`): reads spools from SpoolEase (`listSpools`, `/api/spools`) plus names/temps from the custom-filaments CSV (`getCustomFilaments`), after `checkKey`. `--fields` picks lines from `LABEL_FIELDS` (always printed in that order, empty values dropped); the `qr` field encodes SpoolEase's own S1 tag link (`spoolTagUrl`, mirrors `to_tag_descriptor_s1`'s encoding and default-skipping; SpoolEase can't deep-link a spool, see `docs/assumptions.md`). PDF via pdfkit: one page per label at the label size, QR as vector run rectangles, Helvetica with shrink-to-fit then ellipsis. `--printer` shells out to `lp` with `media=Custom.<size>`. `labelJob.ts` `makeLabels` is the one path from spool selection to PDF/print, shared by `bambu-hando labels`, sync's `--label-output`/`--label-printer` (labels only the spools that run created, via `SyncResult.spoolId`; report `labels`), and the TUI's labels overlay (`tui/overlays/labels/`; choices remembered in `labelSettings.ts`, `configDir()/labels.json`; printers from `lpstat -e`). Tests read the PDF back and decode the drawn QR with jsqr (`test/pdf.ts`); `test/fakeLp.ts` puts fake `lp`/`lpstat` on `PATH`. In PTY tests send one key per write: Ink reads a burst of escape sequences as one escape keypress.
- **API keys** (`secrets.ts`, `secretPrompt.ts`, `keyCommand.ts`, `bambu-hando key set|status|remove`): kept with `@napi-rs/keyring` under service `bambu-hando` (macOS Keychain; Linux pinned to the Secret Service, since its fallback, the kernel keyring, loses keys on reboot), never in a file; `SECRETS` lists them (`3dfp`, overridden by `FILAMENTPROFILES_API_KEY`, prefix `3dfp_`; `spoolease`, the console's security key, overridden by `SPOOLEASE_SECURITY_KEY`, no prefix, so it's checked for emptiness and control characters only and `holdsSecret` skips it; the TUI's Settings stores and forgets it), checked by `validateSecret`, which `loadSecret` also runs on env and keyring values: an unusable key is a setup error (exit 2), named by where it came from, never quoted). `key set` reads a hidden raw-mode prompt (pure `secretKeys`) or piped stdin, refuses keys given as arguments, and nothing prints a value. Tests use a private dbus-daemon + gnome-keyring (`test/keyring.ts`), never the login keyring; the native module keeps its first D-Bus connection for the process's life, so an unreachable keyring is only testable in a fresh process (`keyCommand.e2e.test.ts`).
- **3DFilamentProfiles** (`filamentProfiles.ts` client, `apiQuota.ts`, `filamentProfilesCache.ts`, `filamentProfilesConnect.ts`, `bambu-hando 3dfp usage|spools`): v1 API at `FILAMENT_PROFILES_API`, bearer key from `loadSecret(SECRETS["3dfp"])`; `apiBase` honors `FILAMENTPROFILES_API_URL` only on loopback, and `redirect: "manual"` + an error on 3xx keeps the key from being forwarded. 1000 calls a month (plan-dependent): `QuotaLedger` (`configDir()/3dfp-quota.json`, per `accountId` = 16 hex of the key's SHA-256) takes `X-RateLimit-*` from every response, counts header-less failures as spent, rolls over at 00:00 UTC on the 1st, and `ensure` blocks only on the server's own numbers (an estimate never blocks), and a used-up 0 an hour old lets one call through to check again (`USED_UP_RECHECK_MS`). The client validates documented bounds before sending (a 400 still costs a call). `mySpools` caches the one-call `GET /my/spools` for an hour (`cacheDir()/3dfp/spools.json`), then asks only for the changes (`listSpools(asOf)`: `updated_since` = the last reply's `as_of`; changed spools replace theirs by short code, `deleted` ones go) while the last full list is under `FULL_LIST_EVERY_MS` (a day) old, else, and on `--refresh`, the full list (changes leave out catalog edits such as a renamed color); `forgetSpools` marks it stale after a write, so the next read asks for the changes. `updateSpools` is the bulk `PATCH /my/spools` (up to `MAX_BULK_UPDATES` = 50 per call, one call against the quota, one result per spool in order, a failed one doesn't stop the rest). The list has no Bambu spool or tag IDs; only per-spool GETs do. API facts with sources are in `docs/assumptions.md`. `test/filamentProfilesServer.ts` is the stand-in (quota headers, 401/402 uncounted, 429, documented shapes, `replies` overrides); `test/globalSetup.ts` points `DBUS_SESSION_BUS_ADDRESS` at a dead socket so no test reaches the login keyring.
- **Filament catalog** (`filamentCatalog.ts` storage, `filamentCatalogSync.ts` API side, `3dfp filament|search|fill|catalog`): `node:sqlite` (hence Node ≥ 24) at `dataDir()/3dfp-catalog.sqlite`; summaries, full records (`TdfpFilamentDetail`, no store prices) with `record_at`, merged-id `aliases`, and `fills` progress keyed by search ("all", "brand:x", "material:y", "brand:x,material:y"). `filamentRecord` fetches a missing record, and a `STALE_AFTER_DAYS` (30) old one only with `refreshStale` (CLI `--refresh-stale`; the TUI is meant to ask, only when stale); a failed refresh falls back to the old copy with a warning. `fillSearch` pages 50 at a time up to the API's 20-page cap (`truncated`), resumes at `nextPage`, skips searches completed in the last 30 days, counts searches the API refuses (4xx other than 401/402/408) done, stops on a rejected key, lapsed access or timeout without marking anything done, and skips owned records the API refuses. `monthEndFill` (from `FILL_FROM_DAY` 28 UTC, reserve `FILL_RESERVE` 100) goes owned records → owned brands → unfinished fills → known brands → truncated brands by material → "all" → materials (seen + `COMMON_MATERIALS`), each search once per run.
- **Spool sync** (`spoolSync.ts` planner/applier, `spoolLinks.ts`, `spoolSyncCommand.ts`, `confirm.ts`; `3dfp sync`): SpoolEase ↔ 3DFP. `planSync` is pure: kept links (dropped when a side is gone, `--unlink`ed or replaced by `--link`), chosen links/adds, then unlinked SpoolEase spools matched 1:1 by `spoolsMatch` (squashed brand + material + color: equal with or without each side's type in front, or SpoolEase's name has extra words (the product line) and the color codes agree within `COLOR_TOLERANCE`; extra words on 3DFP's side never fit), else `ambiguous`, else `add` when exactly one catalog filament fits (`addCandidates`), else `suggest`; leftover 3DFP spools are `tdfp-only`. Weights via `weightVerdict` against the link's `agreed` pair (never agreed → SpoolEase wins, since lower-wins would ask forever for a weigh that can't change a correct reading; one side moved → it wins; both → lower wins; < `WEIGHT_TOLERANCE_G`): only ever pushed to 3DFP, since SpoolEase's `edit_spool_from_web` keeps `weight_current` (verdict `weigh` tells the user to weigh). The tag UID goes into `bambu_tag_id` in the same update, and a new spool's into its `POST`. The SpoolEase ID goes into the 3DFP spool's `external_id` as `spoolease:<id>` (`externalIdFor`, `spoolLinks.ts`), in a linked row's update and an add's `POST`; an unlinked 3DFP spool naming a SpoolEase spool there is linked to it ("recorded", before matching by name) when brand and material agree and no other console's book links it (`loadLinks` `linkedElsewhere`); a dropped link clears it (`unlinked` rows carry a `patch`) unless the pair is linked again, and an asked or spoolease-gone unlink whose clear fails keeps its link so the next run tries again; "" reads as no ID; an ID that's unread (undefined) or another app's (no `spoolease:` prefix) is never written. An update the API would refuse (`patchProblem`) fails alone, without a call, instead of failing its batch. `applySync` sends the linked and unlinked rows' updates through `updateSpools`, 50 to a call (`planCalls`: one per 50 updates plus one per add), then each add, keeps a link's old `agreed`/`tag` when its update fails (per spool, or every spool of a refused call), stops calling on a `QuotaError`, and returns links and outcomes in the plan's order plus the `calls` sent; the command `ensure`s the plan's calls first, saves links (`configDir()/3dfp-links.json`, books per account + console host), and `forgetSpools` after writes. It asks via `io.confirm` (`askYesNo`, null without a TTY → "Not applied") unless `--yes`. SpoolEase connection flags resolve through `spooleaseConnectionFrom` (shared with `cli.ts`).
- **3DFP import** (`tdfpImport.ts`, `tdfpImportCommand.ts`, `bambu-hando 3dfp import <code>...`): 3DFP-only spools into BambuStudio and SpoolEase. `prepareImport` refuses unknown, already-linked and Bambu Lab spools and a filament an unlinked SpoolEase spool already is (by `slicerFilament`), reads each filament's record once (`filamentRecord`, catalog first) and, after the SpoolEase check so a refused spool costs nothing, a spool's own calibration only when `hasCalibration` (a failed read refuses that spool alone; a used-up quota stops all) (`spoolProfile`, entries with `source: "spool"`); `importProfile` names it `<brand> <material> <type> <color>` (comma-free), converts 3DFP's mg/cm³ and µm, takes the spool's empty weight and `layered(calibration, settingsFromRecord(record))`. `applyImport` runs `runSync` once per filament with `createSpools: false`, then adds one SpoolEase spool per 3DFP spool (`addSpool`), links each (`agreed: null`) and writes the external IDs 50 to a call. The command asks like `sync` and exits 1 when any code wasn't imported.
- **filament-db export** (`filamentDb.ts`): filament-db's JSON export (contract: `docs/export.md` in `/home/john/gitlocal/filament-db`, `schema_version` 2) at `FILAMENT_DB_EXPORT`, else `$XDG_DATA_HOME`/`~/.local/share` `filament-db/export/catalog.json`; parsed once per path per run (`loadFilamentDb`), no file = no export silently, another schema = a warning (runSync emits it). Lines are found only by id (`FilamentProfile.sourceIds`: `tdfp` from `importProfile`, `spoolmanDb` from `catalogProfiles`; `tdfp` index then `tdfp_aliases`, colors' `spoolmandb_ids`), presets by `SystemProfiles.printerModel` (machine `printer_model` + `nozzle_diameter[0]`), own entry else `fills_in_for`. `buildPreset`'s `manufacturer` (`manufacturerFor`) layers: template → the preset's settings (suspect skipped) or, without one, manufacturer-tier material settings → community `settings` only for uncovered keys (`withoutKeys`) → `FilamentProfile.calibration`; identity keys stay bambu-hando's. `withManufacturerRange` gives runSync/previewPlan's profiles the line's manufacturer range for the CSV. `filamentRecord`/`localRecord` take a fresh export record (`fromExport`) before the catalog's older one or a call. Tests use `test/fixtures/filament-db/catalog.json` (trimmed real export) and `test/fixtures/bambustudio/system-asa/` (Generic ASA, X1/X1C/H2D).
- **TUI** (`src/tui/`, design in `docs/tui-design.md`): `cli.ts` dynamically imports `tui/run.tsx` so headless runs never load React/Ink; `run.tsx` renders `app/Shell.tsx` in the alternate screen and prints the session's run summaries after it. Bubble Tea's architecture in Ink: `core/program.ts` (`Program`: pure `update(model, msg) → [model, cmds]`, a `Cmd` is an async function that dispatches messages), `core/keys.ts` (`KeyPress`, `press()`), `core/types.ts` (the contract: `AppMsg`, `Ctx`, `Resources`, `TabModule`, `OverlayModule`, `RunSummary`). `app/shell.ts` is the shell's pure update: five tabs (`TAB_ORDER`: spools, add, presets, check, settings; `app/registry.ts`), tab/shift+tab, `ctrl+k` palette, `?` help, confirm dialog, toasts, error banner, `q` (exit = highest `RunSummary.exitCode`: 2 setup error, 1 any failure, else 0); it delivers a tab its own messages unwrapped, sends `app/switchTab` to a tab each time it's shown, updates `ctx.resources` before forwarding `app/loaded`, and keeps `q` and `?` global only while the tab's `capturesText` is false (`/` and letters always go to the tab). `app/resources.ts` loads console (spools + custom filaments), presets, SpoolmanDB catalog and the sync check in the background (injectable `Loaders`). Tabs (`tabs/<id>/`: model, update, cmds, View, `index.ts` exporting the `TabModule`): **spools** (landing with a console: inventory, `+` more like this, `b` barcode scan, `l` labels), **add** (Find → Weights → Review → Run: SpoolmanDB drill-down or an imported source, `/` search, Other color…, `e` on Review embeds the presets editor, `runSync`; the sources sit one esc above the brands, and "Your 3DFilamentProfiles spools" among them is `tdfp.ts`/`tdfpCmds.ts`/`TdfpView.tsx`: the unlinked spools previewed from the local catalog (`tdfpImportSession.ts` `previewImport`, shared with `3dfp import`, no API call but the hour-cached list), its own Review (`prepareFromApi`, calls counted, shown again unread for the same ticks and settings) and Run (`applyImport`, `saveImportLinks`), no Weights page, deep link `3dfp`), **presets** (list + detail, `editor.ts` pages per `EDIT_FIELDS` group plus raw settings, review then `writePresetEdits` + the CSV nozzle range), **check** (sections and items, `f` gives presets an ID), **settings** (BambuStudio · SpoolEase (`t` tests the key) · Labels · Import pages; printers saved to `tui.json`, labels to `labels.json` on change). `overlays/labels/` is the labels form with a live preview. `ui/` is the design system (render-only, every line built to an exact width with `string-width`: Frame, Header, Footer, Panel, List with `listWindow`/`moveCursor`/`typeAhead`/`filterRows`, Detail, PageBar, Dialog, TextField with `editText`, Swatch, Bar, Busy, Empty, Title, ConsoleLink). Remembered on disk: `tui.json` printers, `labels.json`, `barcodes.json`.
- **SpoolmanDB** (`spoolmanDb.ts`, `--source spoolmandb`): downloads `filaments.json` + `materials.json` from `SPOOLMANDB_URL` (default GitHub Pages) into `cacheDir()` (`paths.ts`), revalidates with ETag/If-None-Match, falls back to the cache with a warning when the download fails. `catalogProfiles` maps entries onto profiles of one diameter: name `<manufacturer> [material] <product>` (zero collisions across the real database), first weight variant wins, Bambu Lab excluded (BambuStudio ships system presets with their own IDs), temps from entry → `materials.json` → 190-240, and the presets' print and bed temperature from the entry's value, else its range's middle, else `materials.json`'s. `filterProfiles` does brand/material (exact, ignoring case) and `--match` words. The headless CLI requires at least one filter; no match → exit 2; more than `--max-filaments` (default 10) matches → exit 2 before any write, except with `--dry-run`.
- **`FilamentProfile`** (`models.ts`) is the single normalized model; JSON-source defaulting happens in `sources.ts`, SpoolmanDB mapping in `spoolmanDb.ts`. `labelWeight`/`coreWeight` are whole grams because SpoolEase's `AddSpoolDTO` takes `i32`, and 0 means unknown there. Colors are always 8-char uppercase RGBA (`colors.ts`); BambuStudio gets `#RRGGBB`.
- **BambuStudio presets** (`bambuStudio.ts`, `bambuProfiles.ts`) mirror BambuStudio's "Create filament": `SystemProfiles` loads the BBL bundle from `<config>/system` (Generic presets + ancestors, instantiable printers), `template(material, printer)` picks the Generic preset to clone, `buildPreset` merges its resolved settings with the filament's identity and then the source's print settings (`presetSettings.ts`: `FilamentProfile.settings` with print and bed temperature, flow ratio, max volumetric speed and pressure advance; `checkedSettings` keeps BambuStudio's bounds; `applySettings` puts the bed temperature on the hot, textured and engineering plates and their first layers only, never over a template's 0 (plate unsupported); `buildPreset` clamps a source's print temperature into the filament's range (an import widens the range for the spool's own calibrated temperature instead); pressure advance is turned on only for the user's own calibration; `layered` gives precedence: 3DFP calibration, 3DFP record, SpoolmanDB or the JSON file, and Generic only fills what none has; with filament-db's manufacturer data for the line, see the filament-db bullet) (`inherits: ""`, own `filament_id`, `compatible_printers: [printer]`, `version` from the bundle; BambuStudio skips user presets without one). One file per printer, named `<name> @<printer>.json` (BambuStudio derives the preset name from the file name) under `user/<preset_folder>/filament/base/`. `runSync` throws `SetupError` (exit 2) for missing system profiles or unknown printers before writing anything. Existing preset files are kept (`kept` in `PresetOutcome`, `skipped` status when all are) unless `overwritePresets` / `--overwrite-presets`, so BambuStudio-side tuning survives re-runs. The CSV row's nozzle range follows the presets as the run leaves them (`syncedRange`: the first kept preset's range, else the profile's with `presetEdits`), in both `runSync` and `previewPlan`, so a re-sync doesn't undo a range tuned in the preset; `writeMany`'s `adjust` applies `presetEdits` to the presets it writes, never to kept ones. Preset folder and printer default to `BambuStudio.conf` (`bambuDefaults`). Writes are atomic (`atomicWrite.ts` `writeAtomic`: a temp file with its own name per write, then a rename; every file bambu-hando keeps goes through it). Read `docs/assumptions.md` first: it cites the BambuStudio source behind each of these.
- **SpoolEase crypto** (`encryption.ts`): PBKDF2-HMAC-SHA256(key, salt `"example_salt"`, 10k iterations, 32 bytes); wire = no-pad base64(12-byte nonce, always 16 chars) + no-pad base64(ciphertext‖16-byte GCM tag), `Content-Type: application/text`. These mirror SpoolEase itself; changing them breaks compatibility.

## Testing

- `test/fixtures/python-parity.json` holds reference outputs captured from the Python implementation (preset JSON, CSV, spool payloads, AES vectors from `test/fixtures/source.json`). Preset parity was dropped on purpose when presets became full Generic clones; CSV, spool and AES parity remain. Parity tests must keep matching it byte for byte; don't regenerate it to make a test pass.
- `test/fixtures/spoolmandb/` holds 12 real SpoolmanDB entries chosen to cover edge cases (weight/diameter variants, cross-material name clash, multi-color, 8-digit hex, missing temps/spool weight, Bambu Lab) plus the real `materials.json`. `test/spoolmanDbServer.ts` serves them with ETags, records requests, and `failWith` forces errors.
- `test/spooleaseServer.ts` is a real local HTTP server speaking the encrypted protocol (wrong key → 401). It keeps device-like state (`customFilaments`, `spools`, seedable), records `{method, path, body}`, and `server.replies` overrides by `"METHOD /path"` or `"/path"`.
- Parity tests keep the original Python outputs untouched and apply intentional changes on top explicitly (`expectedCsv`, `expectedSpoolPayload` in `test/parity.ts`).
- `test/fixtures/bambustudio/system/` is a trimmed real BBL bundle (Generic PLA/PETG/PETG HF/ABS/PLA-CF/HIPS/TPU chains, X1 Carbon 0.4/0.6). `installBambuStudio(home, conf)` in `test/bambuStudioSetup.ts` copies it and writes `BambuStudio.conf` into a temp HOME; every test that syncs needs it.
- BambuStudio output is redirected with `vi.stubEnv("HOME", tmp)` (`os.homedir()` reads `HOME`).
- `test/globalSetup.ts` points `TMPDIR`, `HOME` and the XDG folders at one `bh-run-*` dir per run and removes it at teardown, so tests `mkdtemp` freely without cleanup and a test that forgets to stub HOME can't write the real user's files (`test/testIsolation.test.ts`). No test may reach the login keyring on any OS: `test/setupKeyringGuard.ts` (vitest setupFiles) lets `@napi-rs/keyring` through only to a private bus `test/keyring.ts` started, and `assertNoLoginKeyring` (`test/keyringGuard.ts`) runs before every spawn of the binary (console commands need the key by flag or env).
- TUI tests come in three layers: pure updates driven with `press()` keys (`test/tab*.test.ts`, `test/shell.test.ts`), render tests with `ink-testing-library` at 80x24 and 120x36 asserting exact line widths (`test/*View.test.tsx`, `test/ui*.test.tsx`, `test/shellRender.test.tsx`, which injects title-only tabs from `registry.ts` `placeholder`), and `test/tui.e2e.test.ts` (built binary in a real PTY via node-pty, drawn by `@xterm/headless`; minimal env on purpose, since CI-like variables switch Ink to non-interactive rendering; `SPOOLMANDB_URL` points at `test/spoolmanDbServer.ts`, so no test reaches the internet).
- The PTY `Terminal.waitFor` also waits (once) until `stty` reports `-icanon` on the pty: Ink draws its first frame before raw mode is on, and a key sent in that window goes through the cooked line discipline and is lost. Match on the drawn screen (`waitForScreen`) for text Ink may redraw in part: Ink 8 rewrites only the changed part of a line. Send one key per write (`pressEach`).
- Exiting the TUI without the shell's quit means Ink handled ctrl+c, so `run.tsx` returns 130. `bin.ts` exits once stdout and stderr are flushed, so a download still in flight never holds the process open.

`docs/assumptions.md` separates documented facts from inferred behavior: read it before touching preset fields or SpoolEase payloads. `docs/testing.md` lists the manual live-validation sequence.

## Multi-agent workflow

- **Hooks** (`.claude/settings.json`, shared scripts in `~/.config/vibe-template/hooks/`): after each edit, `post-edit` runs Biome (`biome check --write`) on only that file, formatting it and applying safe fixes, reports lint errors it can't fix, and flags new code files missing `ABOUTME:`. `npm run lint` checks the whole tree; `npm run format` fixes it. In a turn that edited something, the `Stop` hook runs `npm run typecheck`; a type error blocks stopping and comes back to you to fix. Neither runs tests: run `npm test` (or a targeted `npx vitest run <file>`) before calling a task done. The global `guard-git` hook blocks `--no-verify` and makes every push ask Max.
- **Discovery**: for broad, read-only searches and architecture mapping, use the built-in Explore agent so the lead context stays small, with `ast-grep` for code (not `sg`: on Linux that name can be shadow-utils' switch-group command). Check its claims against `docs/assumptions.md` before acting on preset or SpoolEase details.
- **Parallel workers**: a plan with two or more tasks that touch disjoint files goes through `/fanout` (worktrees in `~/.herdr/worktrees/bambuHando/<branch>`, workers in hc). Never run two editing agents in one working tree. A fresh worktree has no `node_modules` or `dist/`: run `npm ci` there first (`npm test` builds `dist/`). It also gets none of this checkout's Claude memory, and the npm-linked `bambu-hando` binary keeps pointing at this checkout's `dist/`, so workers test with `node dist/bin.js` from their own tree. TUI changes still follow the `tui-ux` skill.
- **Before asking Max to push**: run the `verifier` agent with the spec, then `/code-review` and `/security-review` on the branch diff.
